# 作業三：UDP 群播聊天室

每個聊天室程式加入 `239.0.0.1:8888`。同一個程式透過 `fork()` 分成父、子行程：父行程從鍵盤讀取文字並以 `sendto()` 發送，子行程以 `recvfrom()` 等待群組訊息。

## 手動操作

先在 repository 根目錄執行 `make`，再於同一台 Linux 裝置開兩個終端機，各自從 repository 根目錄執行：

```bash
./build/bin/multicast_chat
```

在其中一個終端機輸入文字並按 Enter；加入同一群組、能收到封包的程式會顯示 `[群組訊息]`。是否也收到自己的訊息，取決於環境的 multicast loopback 設定。

程式使用預設網路介面加入與發送群播，因此執行時可能向所在區域網路送出封包。請只在自己可測試的網路手動操作。自動測試不啟動這個程式。

結束時在每個終端機按 `Ctrl+C`。目前版本沒有 `/quit` 指令，也沒有處理鍵盤 EOF 後的正常離開；請勿用 `Ctrl+D` 結束或把 stdin 接到已結束的管線。

## 核心設定

| 設定／函式 | 在本程式的用途 |
|---|---|
| `SOCK_DGRAM` | 建立 UDP socket |
| `SO_REUSEADDR` | 讓本機多個程式使用相同接收 port |
| `IP_ADD_MEMBERSHIP` | 加入群播群組 |
| `INADDR_ANY` | 綁定本機接收位址，群組介面由環境選擇 |
| `fork()` | 讓鍵盤輸入與訊息接收同時等待 |
| `BUF_SIZE = 1024` | 固定大小的訊息緩衝區 |

原始資料夾同時有兩份程式。本 repository 使用 UTF-8 註解的版本，保留其群播收發邏輯，避免把只差註解編碼的檔案當成不同功能版本。

## 限制與驗證

UDP 沒有在這份程式中加入送達確認、重送、排序或使用者識別。較長的鍵盤輸入也可能分多次送出。跨主機接收還取決於作業系統、虛擬網卡、路由及防火牆是否允許群播。

2026-10-14 已在 WSL Ubuntu 成功編譯此入口；這次整理未執行群播封包傳送，也未重驗跨主機聊天室。若手動測試沒有收到訊息，應先檢查兩邊群組 IP／port 是否一致，再確認介面與網路環境。
